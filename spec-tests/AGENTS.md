# AGENTS.md

## 测试目录边界

- `spec-tests/` 是本仓库唯一的测试实现目录，维护统一执行器、真实浏览器、Android Emulator、物理设备能力与测试模块；产品 `REQ / AC` 统一放在仓库根目录的 `spec/`。
- `run-ac.sh` 默认全量，经本目录执行器调用一次 `tests-auto/test-all.sh`。各模块读取自己的规格和共享 `ENVIRONMENT.md`，新增能力也放在本目录。
- 测试以真实用户使用场景和可复现的真实故障场景为主，可以根据 spec-workflow 的 Environment MCP 规则（真实环境操作与观察服务）新增真实测试模块。
- 不新增脱离真实产品行为链路的单元测试、Mock 测试或假数据验收测试；环境不可用时明确失败，不降级为假环境。
- 测试不导入产品内部模块作为行为替身；共享构建入口负责执行产品 `npm run build`，为真实浏览器提供当前前端快照。
- 正式运行必须自动构建或复用本批次已验证的快照。资源缺失、摘要不一致、源码变化均报错，不能回退远端旧前端。help/discover/dry-run 不构建。
- Service Worker 场景保留本地前端替换，仅按场景需要允许 Worker。agent-device 尚无已验证的本地前端通道时，自动测试必须明确失败。
- 凭据只从环境变量或未提交的 secret 注入，不得写入源码、文档、日志和产物。

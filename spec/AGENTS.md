# 规格目录规则

- `REQ.md` 和 `AC.md` 必须保持面向用户/调用方的外部语义；不得把测试函数名、内部状态、模块名或临时实现写成合同。
- 新建和修改的规格先使用 `status: draft`，直到服务对象、条件、动作、结果和边界经过人工确认。
- 按用户确认的存量迁移范围，`spec/webshell/<tests-auto 模块名>/` 分别维护各模块的 REQ/AC；现有 18 个模块全部接入统一执行链路。每个模块的合同只描述该模块的外部行为，原始脚本和说明通过执行器注册表关联。
- 迁移文档的 REQ 保持 draft 供审阅；既有可执行场景使用 standard 参与全量选择。实际验证状态以每轮报告为准，不能把“已接入”写成“已通过”。
- AC 的 `Profile`、`Gate` 和全局 ID 必须与 `spec-tests/ac-domain-map.yml` 及 Project AC Executor 的发现结果一致。
- 真实场景无法使用时报告环境不可用或失败，不用 Mock、假数据、静态检查或单元测试替代 AC 通过。
- 凭据、目标 URL、设备序列号和运行产物不得进入规格正文。

# 终端连接准备与页面初始化并行

## 背景

用户重新打开普通 LightOS 容器终端时，页面先等待工作区、Worker 与尺寸准备，再建立物理 WebSocket 并等待 Agent 校验。一次实际记录中，工作区数据在约 398ms 返回，物理连接到 523ms 才开始，握手及服务端准备又占用约 240ms。

## 需求目标

目标实例明确后，物理连接和 Agent 准备可以与前端初始化并行执行，减少串行等待。工作区、终端 Worker、配置和尺寸尚未就绪时，不订阅 pane；服务端未就绪或协议不允许接入时，也不启动 pane attach。

连接准备不会改变现有终端恢复、尺寸一致性、显示和输入条件。启动失败、目标变化或页面退出后，不保留无用连接或通过迟到操作接入旧实例。

## 范围

普通 LightOS 容器 WebShell 初次打开时的前端连接编排、单物理连接复用、准备状态保存及取消。保留现有服务端鉴权、Agent 准备与通信协议。

## 非目标

不修改服务端或 Agent，不调整 checkpoint 恢复及 Worker 重建，不为所有实例批量预连接，不改变客户端物理机终端的直连方式。不承诺固定加载耗时；实际提升由相同环境下的手工对比确认。

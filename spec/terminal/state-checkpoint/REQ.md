# 历史达到上限后仍能恢复完整终端

## 背景

长期运行的 TUI 可能只更新底部区域。按字节截断的历史会移除主体绘制和终端初始状态，新页面仅回放历史尾部时出现上部空白；反复重绘无法修复，必须由应用重新输出才能恢复。

## 需求目标

服务端解析正常的容器或受管理的 PC 客户端终端在历史达到保留上限后，用户重新进入仍能获得完整主体、光标及终端模式，并继续交互，无需手动调整尺寸。恢复期间产生的新输出按序应用，不重复或遗漏。

服务端解析状态失效时，仅受影响会话自动使用保留的原始历史回放及后续实时输出，保留原有程序及任务，其他会话继续正常使用。fallback 过程不新增用户界面的提示、弹窗或警告；故障原因与回放路径保留在可复制、下载的错误日志中。

原始历史始终遵守用户配置行数 × 350 字节上限，不因 fallback 推迟裁剪或额外累积历史。不重建失效解析器，不为恢复额外维护健康快照或输出日志。

## 范围

当前协议 Agent 的普通容器 PTY、共用 Go 核心的 PC 客户端 PTY 与支持状态恢复的浏览器。两种实例均通过单个工作区 WebSocket 恢复，不依赖浏览器持久化历史。每个会话保持独立状态，恢复使用明确游标边界，显示前遵守既有回放及尺寸事务。浏览器的默认主题与程序主动设置的颜色分别保留。

## 非目标

不自动替换旧容器 Agent 或重启用户任务。原始历史 fallback 不承诺恢复已裁剪的早期画面或模式，也不承诺消除前端解析缺陷。旧容器协议和 Kitty 图形会话沿用字节回放；PC 需要先升级到受管理的 Go 服务。本次不实现图形资源的服务端状态恢复，不承诺跨不同引擎构建直接导入内部状态。
